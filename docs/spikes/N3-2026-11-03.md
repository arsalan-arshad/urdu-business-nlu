# Spike N3 — Voice/ASR options for Urdu WhatsApp-quality voice-note transcripts

_Access window: 2026-11-03 · researcher: spike-researcher · phase: M0_  
_No personal data, real chats, audio files, or secrets. Not legal advice._  
_Scope: options for a **later** pluggable `transcribe(audio) → text` adapter feeding this library. **Do not build ASR** in this spike._

## Verdict

**Gap partly filled for model choice, open for WhatsApp-domain proof.** Open ASR families with primary docs exist for Urdu (Whisper MIT; MMS and Seamless-M4T CC-BY-NC), and published WER numbers on read/conversational/curated Urdu speech show usable but imperfect transcription — especially for number words that this library must never silently mis-accept. **No primary published WER was found for WhatsApp Opus-compressed Urdu business voice notes**, so N3 does not green-light shipping voice into the validator path; keep ASR as an integrator-supplied adapter after consented domain eval (outside this repo’s no-audio rule).

## Verified vs inferred

### Verified
- Whisper is the only major open family here with **MIT** weights suitable for commercial integrators without NC friction; MMS/Seamless are **CC-BY-NC 4.0**.
- Published Urdu WER on non-WhatsApp speech still leaves double-digit error rates even after fine-tuning large models (~17–19% conversational/read best cases in COLING).
- Lightweight zero-shot Whisper-Small ~33.7% WER on a small curated set — unsafe to auto-trust number words into ledger fields.
- Meta Cloud API documents **Ogg + Opus** for voice messages (send path). Opus compression can raise ASR WER (English Opus study); magnitude for Urdu WA notes **unknown**.
- This repo must not store audio; any future ASR eval stays outside the tree with separate consent (N4 + DATA_AND_PRIVACY).

### Inferred (not proven)
- Number words (`teen`, `derh`, `panch hazaar`) and Roman-Urdu orthography will be higher-error than read news Urdu — hypothesis only; no primary WA-domain count.
- Integrators will prefer Whisper (or a Whisper fine-tune they host) for a commercial `transcribe` adapter unless they accept NC licences.
- Even “good” ASR output must still pass this library’s number-grounding validator; ASR errors that invent or alter quantities should route **confirm/reject**, never silent **auto**.

## Implication for this library (adapter later — not build ASR)

| Layer | Role |
|---|---|
| Integrator `transcribe(audio) → text` | Pluggable; BYO model/hosting; no audio in this repo |
| This library | Parses **text** only; validator grounds qty/amount/date; prefer confirm |
| Eval | Text gold first (M0–M2); ASR+domain WER is a separate later harness with consented audio **outside** repo |

**Default recommendation when voice is eventually offered:** document Whisper (MIT) as the reference open baseline; treat MMS/Seamless as research/NC; require domain WER + silent-error measurement on consented compressed notes before any accuracy claim; never claim WA Urdu WER from this spike.

## Open questions that change the decision

1. Can the owner obtain a **small consented** set of WhatsApp-quality Urdu/Roman-Urdu business voice notes (audio stays off-repo) for a private WER + number-word error study?
2. Is commercial use required for the first adapter demo? If yes, **Whisper MIT** (or licensed commercial ASR) — not MMS/Seamless NC — is the open default.
3. Target script of transcripts: Urdu script vs Roman-Urdu vs mixed — MMS has separate Urdu script adapters; Whisper emits script depending on language/decoding; this changes normaliser design for v1 voice.
4. Acceptable number-word error rate before voice is offered at all (e.g. any digit/`hazaar` substitution → force confirm)?
5. Will Meta’s own client-side voice transcripts ever be the input instead of a local ASR adapter? (Product policy; not measured here.)

## What would change my mind

- A **primary** paper or official eval reporting WER (and preferably number/entity error rates) on **Opus-compressed WhatsApp Urdu** business speech for Whisper or another MIT/Apache model at acceptable levels → accelerate adapter timing and document that baseline.
- Discovery that a permissive, maintained Urdu ASR already meets domain needs with public WA-like eval → narrow “which adapter” rather than “whether voice is premature”.
- Owner decision that voice is out of 90-day scope (Q3) → park N3 follow-up entirely after this landscape note.
