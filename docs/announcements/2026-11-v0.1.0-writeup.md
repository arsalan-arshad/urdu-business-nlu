## The problem I cared about

Builders wiring WhatsApp / ERP / ledger flows for Pakistani SMEs often get informal Roman-Urdu (and mixed English) messages: “PARTY_A ko 5 carton oil bhej do”, udhaar lines, delivery notes. A wrong quantity or amount that slips through is worse than asking a human to confirm. I wanted an **open, tested** parser + eval set — not another closed agent demo.

## What shipped

**urdu-business-nlu@0.1.0** is an **MIT TypeScript library** on npm and GitHub:

- Rules-only path: normalisers → `propose` / `extract` → `validateRecord` → `route`
- Deterministic validator: every number must be groundable in the input (after normalisation / number-word parse)
- Routes: `auto` | `confirm` | `reject` — **silent-error focus** (prefer confirm over a wrong qty/amount)
- **M3 GO** for rules-only v0 (see eval reports in-repo; **no marketing accuracy %**)
- Optional LLM adapter: BYOK, **later** — not in v0

Install:

```bash
npm i urdu-business-nlu
```

## What this is not

- Not a WhatsApp bot / Meta Business API integration
- Not a ledger, payments rail, or ASR product
- Not a hosted SaaS (library + eval; optional hosted API only if demand appears later)
- Not a claim that field accuracy is “solved” — cite [`docs/eval-reports/`](../eval-reports/) if you need numbers

## Eval dataset

The public gold set is **101 synthetic, owner-confirmed** examples under **CC-BY-4.0** (code remains MIT). No real chats, no audio, placeholders only (`PARTY_A`, `SHOP_1`, …). Details and citation: [`docs/DATASET.md`](../DATASET.md). Packaged release: GitHub `v0.1.0-dataset` (Hugging Face optional later).
